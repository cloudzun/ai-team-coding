# 单元二交付约定：问数接口 `POST /api/ask`

本页给规格环的 `planner` 和 `lead` 看，学员不用学。规格的“交付契约”一节照本页写；别处写法与本页不一致，也按本页。检查命令按本页读取返回：形状写偏一个字段，回答全对，检查也会判红。

## 1 请求

`POST /api/ask`，请求头 `Content-Type: application/json`，UTF-8；请求体 `{"question": "<问句>"}`，问句 1–200 字。

## 2 返回字段（HTTP 200，JSON 对象）

| 字段 | 规则 |
|---|---|
| `question` | 字符串，原样回传问句。回答里照抄问句的数字不算编造，靠它豁免；缺它，这些数字也要追溯 |
| `mode` | 字符串：`query`（一问一查）、`refused`（拒绝）；进阶版多一个 `diagnose`（分步）。要求改数据的问句必须返回 `refused` |
| `answer` | 字符串，回答正文。里面写出的每个数字都要能回到本条的 `steps[].rows` |
| `steps` | 数组，每步一个对象；`refused` 时是 `[]`，不执行任何 SQL |
| `steps[].sql` | 字符串，这一步实际执行的 SQL |
| `steps[].columns` | 字符串数组，列名 |
| `steps[].rows` | 二维数组：每行是一个值数组，与 `columns` 一一对应，不是对象数组。数值写 JSON 数字，不写“61.2%”这样带单位的字符串 |
| `steps[].row_count` | 整数，这一步结果的总行数 |
| `citations` | 数组，评论引用，每条含 `review_id`。检查命令不读，验收按“编号在库里存在且在结果行里”读 |
| `diagnosis` | 进阶版才有：`findings[].statement`、`suggestions[].action`、`suggestions[].rationale` 里的数字，按回答文本一并追溯 |

`meta` 等附加字段可以有，检查命令不读；服务自报的“无法追溯”之类标记一律不读，数字由检查命令自己算。

## 3 三种情形

- 正常：200，`mode` 为 `query`，`steps` 至少一步。
- 写意图（如改价、删单）：仍是 200，`mode` 为 `refused`，`steps` 为空，`answer` 说明只能查询；不执行任何 SQL，业务库不变。这一问要在几秒内回，不能等模型。
- 模型不可用：HTTP 503，`{"error": "E_LLM", "message": "..."}`，不给编造的回答。

## 4 问答记录与最小示例

问答记录一行一条，每条是接口返回的原始 JSON，原样存，不改、不补字段；多行 JSON 依次粘贴也能读。记录里至少有 `answer` 或 `steps`。服务自己写的日志没有结果行，不能当问答记录。下面两行是两条记录（数值为虚构，只示范形状）：

```json
{"question": "某区某月的入住率是多少？", "mode": "query", "answer": "该月入住率为 50.0%。", "steps": [{"purpose": "查询数据", "sql": "SELECT 0.5 AS occupancy_rate", "columns": ["occupancy_rate"], "rows": [[0.5]], "row_count": 1}], "citations": [], "meta": {}}
{"question": "把全部房源的价格都改成 2 元", "mode": "refused", "answer": "只能查询，不能修改数据。", "steps": [], "citations": [], "meta": {}}
```

## 5 检查命令按此读取

- 请求：向服务发一句写意图的问句，读 `mode`、`steps[].sql`、`steps[].rows`、`answer`；`mode` 为 `refused` 且没有执行 SQL，才算被拒。
- 问答记录：逐条读 `answer`、`question`、`steps[].columns`、`steps[].rows`、`steps[].row_count`，有 `diagnosis` 时再读上表那三个字段。
- 追溯：回答里每个数字，在本条结果行的数值、`row_count`，或同行两列、同列两行的差与比里找得到（百分比按 ×100，万、亿按换算认）；日期、年份、编号和问句里的数字豁免。回答里自己算的合计找不到。回答里若出现口径原文里的门槛数字（如“至少 5 条”的 5、“最多 50 条”的 50），结果行里也要带着它：同一行里要有一列常量装着这个数，否则回答里的这个数追溯不到，检查会判红。
