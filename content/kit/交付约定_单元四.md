# 单元四交付约定：只读插件、卡片导出与错误码

本页给规格环的 `planner` 和 `lead` 看，学员不用学。规格的“交付契约”一节照本页写；别处写法与本页不一致，也按本页。插件有 4 个只读工具、4 张卡片；基础版只做第一个工具（`homestay_compare`，只发 `GET /api/districts`），进阶版 4 个都做。后端 4 个只读接口的请求参数与返回字段，写在第 1 节。

## 1 只读白名单（只经 HTTP 调后端只读接口，不连库）

- 后端就是项目目录里的服务（默认 8801，被占用就换空闲端口）。插件只经 HTTP 调它，**不打开 `data\homestay.db`，不读后端的 `.env`，不重算口径**。
- 白名单只有 4 条：`GET /api/districts`、`GET /api/trend`、`GET /api/communities`、`POST /api/ask`（问数）。除 `/api/ask` 外只发 GET。
- `/api/ops/*`、`/api/agent/*` **不在白名单**，碰一下就算违约；也没有任何写接口。
- 参数不过关时插件**不发请求**，直接报 `E_HOMESTAY_ARGS`。GET 超时 8 秒，问数 120 秒。

### 1.1 `GET /api/districts`：区级对比（8 个区，每区一行）

- 请求参数：`start`、`end`，`YYYY-MM-DD`，缺省 `2026-07-01`、`2026-09-30`。须满足 `2024-10-01 ≤ start ≤ end ≤ 2026-09-30`，格式不对、日期不存在、越界都回 HTTP 422，`{"detail": "<原因>"}`。上年同期由服务自己取（起止日各减一年），不用传。
- 返回（JSON 对象）：`start`、`end`；`as_of`（等于 `end`，房源数按这一天在线计）；`districts[]`，8 行，每行：

| 字段 | 含义与类型 |
|---|---|
| `district_id` | 区编号，`D01`–`D08` |
| `name` | 区名 |
| `lng_gcj`、`lat_gcj` | 区中心坐标（GCJ-02），卡片不用 |
| `listings` | 整数，`end` 当天在线房源数 |
| `occupancy` | 本期入住率，0–1 小数，4 位；无可售晚数时为 `null` |
| `occupancy_prev_year` | 上年同期入住率，同上 |
| `occupancy_yoy` | 入住率同比，本期减上年同期的差（0–1 小数，4 位），任一为 `null` 则为 `null` |
| `adr` | 本期平均房价（元），2 位；无成交晚数时为 `null` |
| `rating` | 本期评分，2 位；有效评分少于 5 条时为 `null` |
| `market_occupancy` | 本期市场入住率（该区各月市场基准的简单平均），0–1 小数 |
| `adr_prev_year` | 单元四要求后端新增：上年同期平均房价（元），2 位；无成交晚数时为 `null` |
| `adr_yoy` | 单元四要求后端新增：平均房价同比变化率（本期 ÷ 上年同期 − 1），4 位；任一为 `null` 或上年同期为 0 时为 `null`。先舍入再算还是舍入前再算，按规格的口径声明 |

`adr_prev_year`、`adr_yoy` 只加字段：已有字段的名字、口径、顺序都不动。缺这两个字段时，平均房价对比报 `E_HOMESTAY_HTTP`，并提示重启后端。

### 1.2 `GET /api/trend`：月度走势

- 请求参数：`district`，可省；省略或为空就是全公司，否则必须是 `D01`–`D08`，不然回 HTTP 422（“district 必须为空或 D01–D08”）。没有别的参数：返回数据覆盖的全部月份（2024-10 到 2026-09），按月取区间、算去年同月，都在工具里做，不重算指标。
- 返回（JSON 对象）：`months[]`，`YYYY-MM` 升序；`occupancy[]`、`adr[]`、`revpar[]`、`rating[]` 四个数组，与 `months` 等长、逐项对应，值为数字或 `null`。入住率是 0–1 小数；平均房价、每间可售房收入是元；评分是分。
- 工具 `homestay_trend` 的参数：`district`（可省：`D01`–`D08` 或区名，带不带“区”字都行；传区名时先 `GET /api/districts` 取编号）；`metric`：`occupancy`（缺省）｜`adr`｜`revpar`｜`rating`；`from`、`to`（`YYYY-MM`，缺省 2025-10 到 2026-09，须在 2024-10 到 2026-09 之间，跨度不超过 24 个月）。每个月的“上年同月”取同一数组里 12 个月前的那一项，查不到为 `null`。

### 1.3 `GET /api/communities`：小区排行

- 请求参数：`start`、`end`，规则同 1.1，缺省值也相同。后端没有 `district`、`sort`、`order`、`limit` 参数。
- 返回（JSON 对象）：`start`、`end`、`as_of`（等于 `end`）；`communities[]`，每个在 `end` 当天有在线房源、且期内有可售晚数的小区一行，按 `district_id`、`community` 排序，每行：

| 字段 | 含义与类型 |
|---|---|
| `community` | 小区名（模拟名称） |
| `district_id` | 所属区编号 |
| `listings` | 整数，`end` 当天该小区在线房源数 |
| `lng_gcj`、`lat_gcj` | 小区中心坐标，卡片不用 |
| `occupancy`、`occupancy_prev_year`、`occupancy_yoy` | 入住率本期、上年同期、同比差，口径与 1.1 同，0–1 小数，4 位 |

- 工具 `homestay_communities` 的参数：`start`、`end`（边界同 1.1）；`district`（可省，规则同上）；`sort`：`yoy`（缺省）｜`occupancy`；`order`：`asc`（缺省）｜`desc`；`limit`：1 到 20。区筛选、排序、截取前 N 条都在工具里做：排序值为 `null` 的小区不进排行，值相同时按小区名排。

### 1.4 `POST /api/ask`：问数

- 请求：`Content-Type: application/json`，请求体 `{"question": "<问句>"}`，问句去掉首尾空白后 1–200 字，不然回 HTTP 422。
- 返回（HTTP 200，JSON 对象）：`question`（原样回传）；`mode`：`query`（一问一查）｜`diagnose`（分步）｜`refused`（拒答，要求改数据的问句必须如此，`steps` 为空）；`answer`（回答正文）；`steps[]`，每步含 `purpose`、`sql`、`columns[]`、`rows[][]`（每行是值数组，与 `columns` 一一对应）、`row_count`；`citations[]`（评论引用，含 `review_id`）；`meta`（含 `degraded`、`degrade_reason`，模型不可用退回模板回答时标明）。
- 模型不可用：HTTP 503，`{"error": "E_LLM", "message": "..."}`，不给编造的回答。更细的字段与示例见《交付约定_单元二》。
- 工具 `homestay_ask` 的参数：`question`（去掉首尾空白后 1–200 字）；耗时约 30 到 90 秒，超过 120 秒报 `E_HOMESTAY_TIMEOUT`。

### 1.5 工具、请求与卡片

| 工具 | 发的请求 | 卡片 `kind` |
|---|---|---|
| `homestay_compare`：`start`、`end`（边界同 1.1）、`metric`：`occupancy`（缺省）｜`adr` | `GET /api/districts` 一次 | `homestay-compare` |
| `homestay_trend` | `GET /api/trend`；传区名时先 `GET /api/districts` | `homestay-trend` |
| `homestay_communities` | `GET /api/communities`；传区名时先 `GET /api/districts` | `homestay-communities` |
| `homestay_ask` | `POST /api/ask` | `homestay-ask` |

只发上表这几种请求，方法只有 GET 与那一个 POST。区名由 `GET /api/districts` 返回；`district` 对不上时报 `E_HOMESTAY_ARGS`，并把合法取值列出来。

## 2 后端端口可配置

- 端口只在插件配置 `cordis.patch.yml` 的 `config.baseUrl` 一处（缺省 `http://127.0.0.1:8801`）；换端口改这一处再重启 DSH。
- 起后端前先确认端口空闲；插件与检查命令必须指同一个地址，指错时插件报 `E_HOMESTAY_DOWN`（报文里带实际地址）。

## 3 卡片数据导出 `window.__cardExport()`

在 DSH 页面控制台执行 `window.__cardExport()`：同步返回最近一张卡片的结构化数据，还没出过卡片时返回 `null`。它只管对话里的插件卡片；网页看板的那个导出函数是《导出契约》里的 `window.__chartExport()`，两者不是一回事，别混用。

```json
{"tool": "homestay_compare",
 "params": {"start": "2025-01-01", "end": "2025-03-31", "metric": "occupancy"},
 "rows": [{"key": "D08", "label": "钱塘区 49.9%", "value": 0.4989}]}
```

- `tool`：工具名（4 个之一）；`params`：这次调用的参数，原样回填。
- `rows[]`：卡片上画出来的行。`key` 是区编号（`D01`–`D08`）/ 月份 / 小区名；`label` 是卡片上该行显示的文字（行名 + 该行的主数值）；`value` 是机器值——**比例与百分点差用 0–1 小数，金额与评分取原值**。
- 行数与该卡显示的行一致：对比卡 8 行、走势卡按月、排行卡按 `limit`；问数卡取条形图的行，没画条形图时 `rows` 为空数组。
- 与插件工具的结构化返回**同形**：`tool`、`params`、`rows[]` 三个字段都能从工具返回（`execute` 的返回值）与它的 `presentationMeta` 直接得到，不另造字段。

## 4 后端停掉时：报明确错误，不编数字

- 4 个工具都报 `E_HOMESTAY_DOWN`，卡片上只显示错误码与原文（含启动命令）；**没有数字、没有空白卡**。
- 其余错误码：`E_HOMESTAY_ARGS`（参数越界，不发请求）、`E_HOMESTAY_TIMEOUT`、`E_HOMESTAY_LLM`（问数模型不可达）、`E_HOMESTAY_HTTP`（非 2xx 或响应缺字段）。
- 问数 `mode=refused`（拒答）时卡片只显示一段说明，不出数字。

## 5 检查命令按此读取（`v2/lab/tools/u4_check.py`）

- 卡片：读 `--card` 里的 `params`，自己向 `--base` 的同一只读接口再取一次数，逐行比 `value`（比例容差 0.001、金额容差 0.01）；`label` 只查是否含该数值的显示形式（比例一位小数带百分号、金额取整带 ¥、评分两位小数）。
- 只读：向对比接口发一个写方法请求，必须被拒（4xx / 405），之后业务库指纹仍不变。
- 运营库：`--ops` 给了才查 `price_change_requests` 行数没增加；基线里没有行数就记“未检查”，按不通过算。
