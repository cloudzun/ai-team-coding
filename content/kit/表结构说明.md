# 表结构说明

本页列出课程数据库 `homestay.db` 里每张表的表名、字段名、类型和含义，供写 `ref.sql`、读口径表时对照。内容从库自身的结构读出，不含任何数据行、行数或统计值。

## 怎么读这份说明

- “含义”一栏只在《指标口径表》或《运营手册》里能对上时才写，括号里是对应的编号；对不上的字段只给名称和类型，含义写“—”。想知道某个字段里放什么，自己用只读方式查几行：`SELECT * FROM <表名> LIMIT 3;`。
- “键”一栏取自建表语句：主键是这张表里唯一标识一行的字段；外键写明它指向哪张表的哪个字段，两张表要连起来查就用这一对字段做 `JOIN`。
- 日期和月份都以文本（TEXT）存放。口径表里的日期写法（例如 `2026-09-30`、`2026-09`）可以直接拿来比较和截取。
- 查库一律只读打开（`mode=ro`），见 `v2/kit/README.md` 第 4 节。

## 3 表之间怎么连

```text
listings.owner_id -> owners.owner_id
listings.district_id -> districts.district_id
price_history.listing_id -> listings.listing_id
owner_blocks.listing_id -> listings.listing_id
bookings.listing_id -> listings.listing_id
reviews.listing_id -> listings.listing_id
reviews.booking_id -> bookings.booking_id
market_benchmark.district_id -> districts.district_id
price_change_requests.listing_id -> listings.listing_id
maintenance_tickets.listing_id -> listings.listing_id
```

`market_benchmark` 的区、房型、月份三列一起构成主键：同一个区、同一个房型、同一个月只有一行。比较自己和市场时，用 `district_id`、`room_type` 和月份对齐（口径表 M-09）。

## 4 索引

库里已经建了下面这些索引，按这些列过滤或连接会快一些。写 `ref.sql` 时不需要自己建（也不允许建，参考 SQL 只读）。

| 索引 | 所在表 | 列 |
|---|---|---|
| `idx_bookings_checkin` | `bookings` | checkin_date |
| `idx_bookings_listing` | `bookings` | listing_id, checkin_date |
| `idx_listings_district` | `listings` | district_id |
| `idx_benchmarks_district_month` | `market_benchmark` | district_id, month |
| `idx_blocks_listing` | `owner_blocks` | listing_id, start_date |
| `idx_reviews_date_rating` | `reviews` | review_date, rating |
| `idx_reviews_listing` | `reviews` | listing_id, review_date |
| `idx_reviews_rating` | `reviews` | rating |

另有 SQLite 自带的内部表 `sqlite_sequence`，业务查询用不到。
