# 单元三交付约定：运营库与超上限调价请求

本页给规格环的 `planner` 和 `lead` 看，学员不用学。规格的“交付契约”一节照本页写；别处写法与本页不一致，也按本页。检查命令按本页读取运营库和接口返回：表名、状态值、返回字段写偏一处，产品再对，检查也会判红。

## 1 运营库

- 位置：项目目录的 `data\ops.db`（SQLite），与业务库分开；业务库始终只读。
- 服务启动时或第一次巡检时建好这个文件和三张写入表；检查命令先读运营库，缺文件或缺表都判红，且要在至少跑过一次巡检、提交过调价申请之后再跑：`price_change_requests` 一行都没有，也判红。
- 三张表，表名固定：`price_change_requests`（调价申请）、`maintenance_tickets`（整改工单）、`audit_log`（审计日志）。结构取自业务库里的同名表，见《表结构说明》第 2 节。基础版可以不产生整改工单，`maintenance_tickets` 表存在、可以没有行。
- 业务库副本：服务读项目目录的 `data\homestay.db`，检查命令的 `--db` 也指它；缺这个文件服务起不来，先从渔具包的 `db\homestay.db` 复制一份过去。

## 2 检查命令读哪些列

| 表 | 读取的列 | 规则 |
|---|---|---|
| `price_change_requests` | `request_id`、`listing_id`、`current_price`、`proposed_price`、`change_pct`、`status` | 价格是整数；`status` 只取 `待审`、`批准`、`驳回`；`status` 为 `批准` 的行，幅度 `abs(proposed_price ÷ current_price − 1)` 不超过 0.15（手册 P-01） |
| `maintenance_tickets` | `status` | 只取 `待审`、`批准`、`驳回`、`已完成` |
| `audit_log` | 无 | 只查表在不在 |

- 状态值逐字一致，不留空，不另造“已批准”“已提交”这类取值。
- `change_pct` 只随行读出，不参与判定；判定用 `current_price` 与 `proposed_price` 重算。
- `listing_id` 与 `status` 用来避开已有 `待审`、`批准` 申请的房源再发请求，所以要如实写。挑到这类房源时，被拒的 `reject_reason` 里仍要带 P-01 与允许范围；没带，检查会换一套房源再试，最多五套。

## 3 超上限调价请求：`POST /api/ops/preview`

请求体（JSON，UTF-8）：`kind` 为字符串 `"price_change"`；`listing_id` 房源编号；`proposed_price` 正整数；`reason` 字符串；`evidence` 对象，形如 `{"metrics": [{"key": "current_price", "value": 100, "ref": "R00"}]}`。

返回（业务拒绝，如超上限，返回 HTTP 200 加 `ok=false`；请求本身不合法，如字段缺失、类型错、房源不存在，返回 4xx，检查命令不发这类请求）：

- `ok`：布尔。超上限必须是 `false`。
- `rules`：字符串数组，必含 `"P-01"`；可同时含别的规则编号。
- `reject_reason`：字符串，必含允许范围的两个整数：下限 = 当前价 × 0.85 向上取整，上限 = 当前价 × 1.15 向下取整。整数写成连续数字，不带千分位逗号。
- 当前价 = 业务库 `price_history` 里生效日不晚于 2026-09-30 的最近一行的 `weekday_price`；检查命令用同一把尺算范围。
- 通过时返回的 `preview_id`、`row` 等字段，检查命令不读；`evidence` 的内容也不校验，检查命令只读 `ok`、`rules`、`reject_reason` 里的两个整数。

## 4 最小示例（数值为虚构，只示范形状）

某房源当前价 200 元，允许范围 170–230 元，请求 231 元；第一行是请求体，第二行是返回：

```json
{"kind": "price_change", "listing_id": "L999999", "proposed_price": 231, "reason": "示例", "evidence": {"metrics": [{"key": "current_price", "value": 200, "ref": "R00"}]}}
{"ok": false, "rules": ["P-01"], "reject_reason": "P-01 调价幅度超过单次上限 15%（允许范围 170–230 元）"}
```

## 5 检查命令按此读取

- 运营库：三张表在；调价申请至少一行；两张带 `status` 的表状态值在上表范围内；`批准` 的调价幅度不超 15%。
- 接口：发一条拟调价比上限多 1 元的请求，读 `ok`、`rules`、`reject_reason`；`ok` 为 `false`、`rules` 含 `P-01`、`reject_reason` 里取出的整数包含允许范围的下限和上限，才算被拒得对。
- 业务库指纹前后不变。
