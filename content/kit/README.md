# 课程数据包：民宿托管经营系统

本包是本课程的数据与资料。全部数据是**模拟数据**：不对应任何真实房源、房东、住客或平台（库里的 `meta` 表写有同样的声明）。数据覆盖 2023-10-01 至 2026-09-30，共 36 个月。

## 1 你会拿到什么

| 位置 | 内容 | 用途 |
|---|---|---|
| `student-pack/指标口径表.md` | 指标口径，编号 C / M / T | 所有指标按本表计算；单元二问答与单元三巡检共用 |
| `student-pack/运营手册.md` | 定价、质量、整改、不调价规则，编号 P / Q / F / N | 巡检建议必须引用规则编号 |
| `db/homestay.db` | SQLite 数据库，约 40 MB，随课堂分发 | 问答与巡检的数据来源 |
| `表结构说明.md` | 库里每张表的表名、字段名、类型和含义 | 写参考 SQL、读口径表时对照；写 `ref.sql` 之前先看一遍 |
| `导出契约.md` | 页面导出契约 `window.__chartExport()`：字段、`points`、0–1 小数、`value` 与 `label`、示例与控制台导出命令 | 写需求、规格、参考 SQL 时的唯一依据 |
| `交付约定_单元二.md` | 单元二问数接口 `POST /api/ask` 的请求与返回字段、问答记录的写法、示例 | 给规格环的 `planner` 和 `lead` 看，写规格“交付契约”一节时照它写；学员不用学 |
| `交付约定_单元三.md` | 单元三运营库 `data\ops.db` 的三张写入表、列与状态值，超上限调价请求的接口与被拒时的返回字段、示例 | 同上 |
| `交付约定_单元四.md` | 单元四薄插件的只读白名单、端口配置、卡片导出 `window.__cardExport()` 的字段、后端停掉时的错误码 | 同上 |
| `checksums.txt` | 数据内容校验和、文件 SHA-256 与字节数 | 核对拿到的东西有没有变 |

自检脚本 `env_check.py`、`db_fingerprint.py` 在 `v2/lab/tools/` 下，随课程材料一起给。

不知道某张表有哪些字段时，先翻 `表结构说明.md`，不用自己写脚本去探查。它只写结构，不含数据行；字段里放了什么，用只读方式查几行自己看。

本次分发的库规模：`listings` 633、`owners` 218、`bookings` 148,793、`reviews` 66,062、`price_history` 1,581、`owner_blocks` 2,531、`market_benchmark` 1,152。行数不用背，`env_check.py` 会打印。

## 2 怎么拿到数据库

数据库以文件形式随课堂分发。放进本包的 `db/` 目录，目录已经留好：

```
v2/kit/
  checksums.txt
  表结构说明.md
  db/
    homestay.db      <- 放到这里
  student-pack/
    指标口径表.md
    运营手册.md
```

`db/` 的内容已被 `.gitignore` 忽略，把库放进 `db/` 不会让你的仓库变大。放好之后先做第 3 节的核对，再开始用。

## 3 怎么核对

一次全查：

```
python v2/lab/tools/env_check.py
```

默认读 `v2/kit/db/homestay.db` 与 `v2/kit/checksums.txt`。文件放在别处时显式指定：

```
python v2/lab/tools/env_check.py --db <库文件路径> --kit <数据包目录>
```

它逐项打印绿色或红色并给结论；自动项全部通过时退出码为 0。红色项后面的提示就是改法。

两个校验和的分工：

- 判定"数据是不是同一份"看 `checksums.txt` 里的 `db_content_sha256`（数据内容校验和：所有表按表名排序、每张表按主键排序后逐行序列化再算 sha256，与 SQLite 文件的字节布局无关）。
- `db_file_sha256` 与 `db_bytes` 用来确认"拿到的是课堂分发的同一个文件"。同一份数据重新生成时文件字节可能不同，这时只看内容校验和。
- `student-pack/` 下两份资料的 SHA-256 也登记在表里。两份资料是只读资料，不改。

文件级指纹用于前后对比：

```
python v2/lab/tools/db_fingerprint.py v2/kit/db/homestay.db
```

它打印库文件的 SHA-256 与字节数。把输出存成文件，之后带上这个文件再跑一次：

```
python v2/lab/tools/db_fingerprint.py v2/kit/db/homestay.db 上次输出.txt
```

末行给"不变"或"已变"。业务库在整门课里应始终是"不变"：单元三的写入落在独立运营库，不动业务库；若看到"已变"，说明业务库被写过。"这份数据是不是我预期的那份"仍用内容校验和判断。

## 4 只读纪律

- 查数据一律用只读方式打开，例如 `sqlite3.connect("file:...?mode=ro", uri=True)`。`env_check.py` 会实测一次写入被拒。
- 不要在 `db/` 里建表、改数据。业务库只读、指纹不变；单元三要写入的内容放独立的运营库里（在你自己项目目录的 `data\` 下），不写业务库。
- 不修改 `checksums.txt`、`表结构说明.md`、`导出契约.md`、`交付约定_单元二.md`、`交付约定_单元三.md`、`student-pack/` 下两份资料、`.gitignore`。
- `db/` 里只放这一个库文件，不要把库提交进版本库。

## 5 人工确认项

`env_check.py` 末尾会打印三项人工勾选：浏览器、coding agent、大模型接口。这三项脚本判定不了，按清单自己确认一遍。

## 6 出问题时

把 `env_check.py` 的整段输出（含末行结论）贴出来，比自己描述"打不开数据库"有用。
