# 判据清单模板 · 单元一 数据看板（基础版）

分析角色主笔，技术角色确认每条机器判据真的跑得起来。课上判据总数不超过 8 条；基础版建议 5 条机器判据加 3 条人眼判据。

## 怎么填

- 编号：机器判据用 M1、M2……，人眼判据用 H1、H2……
- 判据：一句话写清“判什么”，带对象 id 或页面位置。
- 机器或人眼：机器判据写出用什么命令或脚本；人眼判据写“人眼”并指向《人眼抽查记录表》里人眼三问的哪一问。
- 期望值来源：只能是指标口径表的编号、运营手册的规则编号、需求里的某句话、数据库本身（包括自写的 `ref.sql`）。
- 怎么故意做错会变红：写一个具体的错误实现，并写出它会让哪一行变红。写不出来的，回去用《判据筛查清单》的两问再筛一次。

## 建议的覆盖

基础版有五个方面要有判据覆盖。你们组可以换一种分法，但每个方面都要有对应的行。

| 方面 | 对应哪几行 |
|---|---|
| 关键数字与参考 SQL 一致 | |
| 筛选后对象集合与参考 SQL 逐元素相同（指标卡、趋势、结构随选区变；对比图不随选区收缩，仍是 8 个区） | |
| 每张图都能导出，且与自算值逐点一致 | |
| 库文件指纹前后不变，没有新增库文件 | |
| 界面上的模拟数据声明与库内声明原文一致 | |

人眼判据建议三条，各对应人眼三问的一问：页面上抽看的数字与检查输出对得上（第 1 问）；四类视角各一张可读的图，并核对图例与坐标轴（第 2 问）；页脚声明、口径歧义声明与页面行为一致，没有错字、空白卡、乱码（第 3 问）。

## 交接前自检

- [ ] 判据总数不超过 8 条。
- [ ] 每条机器判据都写明了用哪条命令跑。
- [ ] 每条判据都过了“零工作量能不能过”“照错的实现写会不会被打红”两问。
- [ ] 期望值来源里没有“感觉”“经验”“大概”。
