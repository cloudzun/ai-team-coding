# 示范任务书 · 单元一 数据看板（基础版）

这是按《任务书模板》填好的一份，供你们组对照着写自己的版本，与第 4 章第 3 节的成品任务书是同一份。它是一种写法，不是标准答案：视角、文字、对象 id 都可以不同，只要每一栏都能判真假。下面“---”之后的内容可以整段贴给 lead，从“### 1”到“### 迭代记录”。

---

### 1 做什么，给谁看

做一个单页数据看板，只读打开课程数据库，四类视角各一张图：

- 状态：指标卡，最近一个月（2026-09）的入住率、平均房价、每间可售房收入、平均评分，每项带同比与环比。
- 趋势：折线图，过去 36 个月的按月入住率。
- 对比：分组柱状图，各区 2026Q3 与 2025Q3 的入住率对比，叠加一条市场基准。
- 结构：按房型给出截至 2026-09-30 在线房源的占比，图型不限。

联动只做一条路径：在对比图上点选一个区，指标卡、趋势、结构三处切到该区；再点一次回到全公司。对比图本来就是 8 个区并列，选区后不收缩，只高亮选中的区。

给托管公司运营负责人看。他看完决定下一季度把整改和调价的精力先投到哪个区。

### 2 本轮要证明的一件事

运营负责人打开页面，一屏之内就能判断哪个区在掉队，并且不是大盘的原因：本区 2026Q3 对 2025Q3 下滑，而同期市场基准没有同样下滑。页面上每个关键数字，都和规格环参考 SQL 算出的一致。

做完以后，如果把“本期”和“上年同期”两个系列对调，检查仍然全绿，就是没做到。

### 3 数据与资料在哪

渔具包在 `..\v2\kit`（从我们的工作目录 unit1-board 算起），下面的路径都相对它。请你先读，数据库只读：

- `db\homestay.db`：课程数据库，数据到 2026-09-30，全部是模拟数据；用到的表是 `bookings`、`listings`、`owner_blocks`、`reviews`、`market_benchmark`、`districts`、`meta`；
- `student-pack\指标口径表.md`：指标口径，所有指标按它算；
- `student-pack\运营手册.md`：规则手册；
- `表结构说明.md`：每张表的字段与含义，写 SQL 前先看；
- `导出契约.md`：页面导出数据的形状，见第 6 栏；
- `checksums.txt`：数据校验和，不改；`student-pack\` 里的资料也不改。

我们组的数据事实卡是 `..\records\数据事实卡.md`；课程给的几段现成查询和它们的输出是 `..\records\事实卡查询.sql` 和 `..\records\fact_runs.txt`。这些供你参考，`records` 里的其他文件不用读；口径只认口径表，查询不是验收依据。

`v2\checkpoints\`（课程的参考实现）不给任何子 agent 读，也不要复制进项目目录；检查命令和坏夹具不给 builder 读。

### 4 边界与不做清单

- 不做：自然语言问答、巡检 Agent、插件；登录与权限、导出下载、移动端适配、深色模式、行政区边界底图、实时刷新。
- 不写库，不改渔具包里的任何资料。
- 必须标注：页脚逐字显示数据库 `meta` 表里 `notice` 一项的原文；对比图的图例或图注写明“2026Q3 对 2025Q3”，并写明市场基准的合成方式（按第 5 栏我裁定的写）。

### 5 关键口径歧义怎么处理

口径表没写死、你和验收方可能理解不同的地方，一律不自己定，也不让验收方按自己的理解判过：先列 A/B 两个选项问我，各带代价，给推荐，我回字母，回之前不按任何一种理解施工。

第 3 章的事实卡里，我已经看到两处：

1. 平均评分的“当期”按哪个日期归属：M-07 写“当期评论”，没写按评论日期，还是按评论所属订单的入住日。
2. 对比图每区一根市场基准柱，区级一个数怎么由各房型合成：M-09 只定义到同区、同房型、同月。

舍入方向（含负数）、同比先算差还是先舍入、空值与样本不足怎么显示，同样处理。你读口径表发现这里没列的，也同样处理。我的裁定写进规格的口径声明，页面行为必须和它一致。

导出数据的形状和比例的量级（字段名、0–1 小数）由第 6 栏的课程契约规定，不算口径歧义，不要拿来问我。

### 6 验收方式

检查命令在工具箱里。工具箱和参考 SQL 不要给 builder 读；`..\mine\` 里只放开工前的库指纹，你和所有子 agent 都不读不改，只有检查命令用 `--before` 取它。

参考 SQL 由规格环的 planner 写、评审环审，我不写：按渔具包《导出契约》第 6 节的段头格式，全公司版 `ref.sql` 另写一份选区版 `ref_d08.sql`；两份都放在运行目录的 `ref\` 下，段头的对象 id 与下面的对象清单逐字一致。验收由 qa 子 agent 跑。

我要看到的证据：

1. 页面按《导出契约》导出，形状按渔具包里的 `导出契约.md`，不用问我，也不用另选：
   - 页面提供全局函数 `window.__chartExport()`（同步或返回 Promise 均可），返回可转成 JSON 的对象，含 `page`、`filters`、`kpis`、`charts`；
   - 图表点位写成 `charts[].series[].points[]`，每点 `{x, value, label}`，字段名只用 `points`，不用 `data`；
   - 比例类数值（入住率、占比、同比变化率等）的 `value` 一律用 0–1 小数，不写百分数；页面显示“63.7%”，`value` 是 0.637，`label` 是“63.7%”；金额、评分取原值；
   - `value` 取自已渲染的图表实例或页面节点，不能把后端接口的原始数据直接转发；`filters` 写当前筛选状态，联动后随之变化；
   - 对象 id：`occupancy_latest`、`adr_latest`、`revpar_latest`、`rating_latest`（指标卡）；`occ_monthly`（系列“入住率”）；`district_yoy`（系列“本期”“上年同期”“市场基准”，x 为区名，永远 8 个区）；`room_type_mix`（每个房型一个系列）。
2. 页面上的关键数字与参考 SQL 一致：比例容差 0.001，金额容差 0.01，评分按比例档；全部 PASS（退出码 0）。
3. 把“本期”和“上年同期”对调（`--swap`）再对账，必须变红（退出码 1）。
4. 在对比图上选 D08 后再导出一次，用 `ref_d08.sql` 对账；对比图仍是 8 个区，只高亮选中的区；`occ_monthly`、`room_type_mix` 和指标卡随选区变化，`district_yoy` 不变。这一条由 qa 在规格判据里验，结论写进 `L1-QA.md`，我在 G2 之前读。
5. 库文件指纹前后不变。检查命令带上开工前存的指纹（`--before`），把它作为一项查出来。
6. 规格里标了“待人眼”的判据，在 G2 之前都要有结论；页面上标签有没有截断重叠、颜色分不分得开、图注有没有写明口径，也写成待人眼的判据。
7. 放行 G2 之前：检查命令可以让 qa 替我跑，同一条命令正向一次、负向一次，命令和输出由它自己写进 `evidence/user-check.md`；我自己读输出，在同一份文件里写人眼三问各一行和一行结论，这四行不许别人代写。缺这份记录，你不要来问我 G2。

### 7 流程要求

- 按课程副本技能 `gstack-sprint` 的 L1 课程版（第 1.5 节）跑，档位和版本计划在环 0 先给我看。
- 看板要开，每环结束先更新看板再汇报。
- 子 agent 组队干活：lead 不写产品代码，不验收，不亲自取证；验收者长时间无产出就换人。
- G1 我回字母之前不派施工。
- 技术选型（语言、库、服务形态、静态资源从哪取、端口）不必问我，你带推荐自己定，记进看板，报一句就行；我事后可以否决。
- 我回“都按推荐”只表示这一批口径按你的推荐走，不代表放弃把关；涉及验收口径和对外契约的条目，请单独列在最前面、逐条标出，我逐条回字母，不接受一句话全部放行。
- 提 G2 之前，先检查我的抽验记录 `evidence/user-check.md` 在不在、“待人眼”的判据是否都已有结论；没齐就先告诉我缺什么，不要直接问我放不放行。
- commit 之前把证据包给我看，我放行才提交；放行同时覆盖收尾文档的追加 commit，收尾不用再单独问我；只 commit，不 push。
- 起产品服务供我抽验的事交给验收子 agent，你不自己起服务，也不读截图下判断。

### 8 端口与环境事实

- 系统是 Windows，命令行用 PowerShell；有 Python 和 Node.js。
- 我们要做的数据看板，服务默认用 8801；起之前先查端口，被占用就换一个空闲端口并告诉我。同一时刻只留一个服务实例，用完关掉并复查端口已释放。
- 开场先告诉我当前工作目录。开工前请你替我做这几件事，并把命令和输出给我看：建项目目录 `unit1-board` 和 `mine`（单元二起，从上一单元已 commit 的版本复制，含 `.env`），`git init` 或保留历史，把业务库开工前指纹存到 `mine\` 里；然后把工作目录切到项目目录再开工。`mine\` 里只放这一份指纹，之后你和子 agent 都不读不改。

### 9 回报方式

- 每次汇报固定三行：现在（环号、环名、门禁）、变了（本环新增的 ⚡ 和 ⏸，没有写“无”）、要你（有 ⏸ 才展开）。第一行原文复述看板的“现在在哪”。
- 问我时在正文里列 A/B，各带代价，给推荐，我回字母。G1、G2 没有默认，我不回就不动。
