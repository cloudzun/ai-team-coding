# 口号改写对比卡

口号式的要求听起来对，但没有人能判它做到没有。可判式的写法有三个特点：写明谁、看什么、和什么比；期望值有来源；做错一处会被打红。下面是 5 组数据看板场景的对照，业务背景都是通用的，改写之后每条都过了“零工作量能不能过”“照错的实现写会不会被打红”两问。

## 第 1 组　整体目标

| | 写法 |
|---|---|
| 口号式 | 做一个数据看板，帮助运营掌握各区的经营质量 |
| 为什么判不了 | 没有“谁”，没有“看完做什么”，“掌握”无法检查；零工作量也能说自己做到了 |
| 可判式 | 运营负责人打开页面一屏，就能说清：最近一个月的四项指标；各区入住率与自己的上年同期、与市场基准的对比；页面上的关键数字与参考 SQL 算出的一致 |
| 怎么判 | 机器：关键数字与参考 SQL 逐个对；人眼：人眼三问里的第 1 问“数字对上了吗” |

## 第 2 组　数字对

| | 写法 |
|---|---|
| 口号式 | 页面上的数据要准确 |
| 为什么判不了 | “准确”没有标尺；没有说和谁比、容差多少 |
| 可判式 | 指标卡的入住率、平均房价、每间可售房收入、平均评分，与自写参考 SQL 的结果一致；比例容差 0.001，金额容差 0.01 元 |
| 怎么判 | 机器：检查脚本按对象 id 对齐、比对数值 |

## 第 3 组　图不能装反

| | 写法 |
|---|---|
| 口号式 | 对比图要正确显示本期和上年同期 |
| 为什么判不了 | “正确”没有说怎样对；只验接口数字时，两组柱装反也通过 |
| 可判式 | 对比图每个区的“本期”“上年同期”“市场基准”三个系列，按系列名从已渲染的图表里导出，与参考 SQL 逐点比较；把两个系列名对调后，检查必须变红 |
| 怎么判 | 机器：导出函数加检查脚本，含负向自检；人眼：抽一个点，图上读到的数与参考 SQL 对上 |

## 第 4 组　联动

| | 写法 |
|---|---|
| 口号式 | 选择某个区后，页面要联动 |
| 为什么判不了 | “联动”没有说哪些图、变成什么；只验“发出了请求”，图没重绘也通过 |
| 可判式 | 在对比图上选中一个区后，指标卡、趋势、结构三处导出的对象集合，与参考 SQL 在该区的结果集合逐元素相同；筛选状态显示该区名；再点一次，回到全公司的集合；对比图不随选区收缩，仍是 8 个区，只高亮选中的区，不放进这条的集合比对 |
| 怎么判 | 机器：筛选前后各导出一次，按集合比对；人眼：筛选条与图标题随之变化 |

## 第 5 组　标注与可读

| | 写法 |
|---|---|
| 口号式 | 图表要清晰美观，注明数据来源 |
| 为什么判不了 | “清晰美观”没有标准；“注明”没有说写什么、放哪里 |
| 可判式 | 页脚显示数据库内模拟数据声明的原文，逐字一致；市场基准的图例或图注含“简单平均”；四类视角各有一张图，标签无截断无重叠，颜色能分辨，图例与坐标轴有名称 |
| 怎么判 | 机器：页脚文字与库内声明比对；人眼：人眼三问里的第 2 问“一眼看得懂吗”与第 3 问“有没有明显错的” |

## 改写自己的口号

挑一句你们组需求里最像口号的话，照下面四步改写。

1. 它的“谁”是谁？看完要做什么决定？
2. 它的“看到什么”，能不能在页面上指出来？
3. 它和什么比，期望值来自口径表、需求还是数据库？
4. 故意做错一处，它会变红吗？不会，就回到第 3 步。
