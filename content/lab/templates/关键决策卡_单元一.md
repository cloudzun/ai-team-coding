# 关键决策卡 · 单元一 数据看板

每个实战单元有 2 到 3 个必须由人拍板的点。AI 可以给推荐，但这三件事的结论由你们组写下来。每张卡四栏：问题、判断标准、反例、我们组的决定与理由。前三栏是课程给的，第四栏由你们组填。

## 卡一　判据写到哪一层

**问题：** 一条关于数字的判据，验接口返回的数，还是验到用户眼睛看到的那张图？

**判断标准：** 想象一个故障：图装反了，比如“本期”和“上年同期”两组柱对调。如果这条判据在这个故障下仍然通过，就必须升级成验图；升级不了的，降为人眼判据，并写明人要看什么。

**反例：** 判据只比接口返回的数字，对比图把本期和上年同期装反时，所有判据照样通过。（判例一）

## 卡二　“不许照抄参考 SQL”放哪

**问题：** 要求施工方“应用里的 SQL 自己写，不许照抄参考 SQL”，这类机器判不可靠的约束，写进判据，还是降为人眼？

**判断标准：** 先问零工作量能不能过。能过，就不是判据，降为人眼，并写明人对照什么看：结构、写法、取数范围，而不是只看文件名。

**反例：** 判据只搜代码里有没有参考 SQL 的文件名，施工方把 SQL 原文粘进代码里，这条照样通过。

| 如果降为人眼：对照什么看，记在抽查记录表的哪一行 | |

## 卡三　口径歧义由谁定

**问题：** 口径表没写死的地方，比如负数怎么四舍五入、同比先算差还是先舍入、空值显示什么，由谁来定？

**判断标准：** 双方理解不同时，由人裁定，并写回需求的“口径歧义声明”一栏；验收方不得按自己的一种理解判过。裁定之后，页面行为必须和声明一致。导出数据的形状和比例的量级（字段 `points`、比例类 `value` 用 0–1 小数）不在此列：它们由渔具包里的 `导出契约.md` 规定，不裁定、不选，更不能在回“全推荐”时顺手带过。

**反例：** 负数的舍入方向没写清，验收方按自己的理解判了通过，施工方按另一种理解做，两边都以为自己对。
