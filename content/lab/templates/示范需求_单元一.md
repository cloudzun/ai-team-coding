# 示范需求 · 单元一 数据看板（基础版）

这是一份填好的需求，供你们组对照着写自己的版本。它是一种写法，不是标准答案：视角、文字、对象 id 都可以不同，只要每一栏都能判真假。栏目顺序和《需求模板》一致。

## 1 做什么

一个单页数据看板，读课程数据库（只读），含四类视角各一张图：

| 视角 | 图 | 内容 |
|---|---|---|
| 状态 | 指标卡 | 最近一个月（2026-09）的入住率、平均房价、每间可售房收入、平均评分，每项带同比与环比 |
| 趋势 | 折线图 | 过去 36 个月的按月入住率 |
| 对比 | 分组柱状图 | 各区 2026Q3（2026-07-01 至 2026-09-30）入住率与 2025Q3（2025-07-01 至 2025-09-30）的对比，叠加一条市场基准（取本期三个月、同区各房型的简单平均） |
| 结构 | 堆叠柱状图 | 截至 2026-09-30 在线房源的房型结构占比（按房型计数，口径见口径表 M-11、C-03） |

联动只做一条路径：在对比图上点选一个区，指标卡、趋势、结构三处跟着切换到该区；再点一次，回到全公司。对比图本来就是 8 个区并列，不随选区收缩，只把选中的区高亮。

## 2 给谁（看完做什么决定）

- 看的人：托管公司运营负责人。
- 要做的决定：下一季度把整改和调价的精力先投到哪个区。

## 3 达到什么效果

运营负责人打开页面，一屏之内就能说清三件事：

1. 最近一个月经营得怎么样：四项指标各是多少，同比、环比往哪个方向变。
2. 过去 36 个月的季节规律：哪几个月是旺季，哪几个月是淡季，每年是否重复。
3. 哪个区在掉队，并且不是大盘的原因：拿这个区 2026Q3 的入住率和自己的 2025Q3 比，再和市场基准比；自己下滑而市场基准没有同样下滑，才算掉队。

页面上每个关键数字都和自己写的参考 SQL 算出的一致。

做完以后，怎么证明我没做到：把导出数据里“本期”和“上年同期”两个系列名对调，再与参考 SQL 核对，检查必须变红；仍然全绿，说明检查没有读到图上的数据，判据要重写。

| 步 | 动作 | 期望看到 | 证明什么 |
|---|---|---|---|
| 1 | 打开首页 | 顶部指标卡：2026-09 的入住率、平均房价、每间可售房收入、平均评分，各带同比与环比；页脚有模拟数据声明 | 事一成立；状态视角；声明标注到位 |
| 2 | 看趋势图 | 36 个月的入住率折线，横轴为年月，纵轴为入住率 | 事二成立；趋势视角 |

## 5 边界与标注

- 本版范围：四类视角各一张图，一条联动路径，只读打开数据库。
- 留给后续单元：自然语言问答（单元二）、巡检 Agent（单元三）、插件（单元四）。登录与权限、导出下载、移动端适配、深色模式、行政区边界底图、实时刷新，也留给后续版本。
- 必须标注的内容：
  - 全部数据为模拟数据：页脚固定显示数据库 `meta` 表里 `notice` 一项的原文，逐字一致。
  - 市场基准为模拟数据，区级市场入住率是各房型的简单平均：对比图的图例或图注里写“简单平均”。

## 6 口径歧义声明

下面五条是示范里的裁定，你们组可以裁成别的，但要写明，并让页面照做。

| 歧义点 | 本需求的裁定 | 页面上怎么体现 | 怎么核对 |
|---|---|---|---|
| 舍入方向（含负数） | 页面上比例显示为百分数、保留一位小数（导出的 `value` 仍是 0–1 小数，见第 7 节）；按绝对值四舍五入（远离零取整），负数与正数对称：同比 -0.25 个百分点（-0.25 pp）保留一位小数，显示为 -0.3 pp | 指标卡、图上标签、同比数字用同一规则 | 抽 3 个数字，用参考 SQL 的原值手算一遍，与页面显示逐个对 |
| 同比怎么算 | 同比是两个期间的入住率相减，单位百分点（pp）；先用没舍入的原值相减，再对结果舍入 | 页面上同比一栏写“x.x pp”；不用两个已舍入的数相减 | 取一个区，用原值算差，再与页面显示对 |
| 空值与样本不足 | 没有数据显示“—”，不画成 0；平均评分的有效评分少于 5 条时显示“样本不足”，不显示数值（口径表 M-07） | 悬停或图注写明“—”表示无数据 | 在参考 SQL 里挑一个评分不足 5 条的情形，看页面是否显示“样本不足” |
| 评分“当期”按哪个日期归属 | 口径表 M-07 写“当期评论”，没写按哪个日期。本需求裁定：按评论日期（`reviews.review_date`）落在期内的评论来算，不按评论所属订单的入住日（`bookings.checkin_date`）归期 | 指标卡的平均评分、趋势里的评分都用这条；页面或图注写明“按评论日期” | 参考 SQL 的评分段只用 `review_date` 做期间条件，段内注释写明这一裁定；两种归期的结果一般不同，别照抄订单的归期规则 |
| 对比图的期间 | 本期取最近一期 2026Q3（2026-07-01 至 2026-09-30），上年同期取 2025Q3（2025-07-01 至 2025-09-30）；入住率用期间总成交晚数 ÷ 期间总可售晚数，不用各月入住率再平均 | 图例或图注写明“2026Q3 对 2025Q3” | 参考 SQL 的 `district_yoy` 段写这两个期间，段内注释写明起止日 |

## 7 交付契约

页面提供全局函数 `window.__chartExport`，同步返回或返回 Promise 均可，结果是一份可转成 JSON 的对象：

```json
{
  "page": "dashboard",
  "filters": {"district": "全公司"},
  "kpis": [{"id": "occupancy_latest", "value": 0.6123, "label": "61.2%"}],
  "charts": [
    {
      "id": "occ_monthly",
      "title": "按月入住率",
      "series": [
        {"name": "入住率", "points": [{"x": "2026-01", "value": 0.6123, "label": "61.2%"}]}
      ]
    }
  ]
}
```

本节的形状取自渔具包里的 `导出契约.md`（课程统一导出契约），原样使用，不属于口径歧义，不用裁定。

约定：

- 图表点位只写成 `charts[].series[].points[]`，每点 `{x, value, label}`；字段名不用 `data`、`values` 等别名。
- **比例类数值（入住率、占比、同比变化率等）的 `value` 一律用 0–1 小数**，不写百分数；差值也用 0–1 小数差（0.05 就是 5 个百分点）；金额、评分取原值。页面显示“61.2%”，导出的 `value` 是 0.6123，`label` 是 “61.2%”。这两句要放在一起记：`value` 是机器值，`label` 才是显示文字；把显示值 61.2 塞进 `value`，检查脚本会判红。
- `value` 取自已渲染的图表实例或页面上渲染出来的节点，不能把后端接口的原始数据直接转发。否则图装反了，导出的数据仍然“正确”。
- `label` 是页面上实际显示的文字；取不到时写 `null`。
- `filters` 写当前筛选状态；联动后要随之变化。
- 对象清单：

| id | 类型 | 含义 | 系列名 |
|---|---|---|---|
| occupancy_latest | kpi | 最近一期入住率 | — |
| adr_latest | kpi | 最近一期平均房价 | — |
| revpar_latest | kpi | 最近一期每间可售房收入 | — |
| rating_latest | kpi | 最近一期平均评分 | — |
| occ_monthly | chart | 按月入住率，36 个月 | 入住率 |
| district_yoy | chart | 各区 2026Q3 对 2025Q3 的入住率对比，x 为区名；永远是 8 个区，选区后不收缩 | 本期、上年同期、市场基准 |
| room_type_mix | chart | 截至 2026-09-30 在线房源的房型结构占比，x 为筛选范围，每个房型一个系列 | 房型名 |

- 联动后各对象怎么变：指标卡、`occ_monthly`、`room_type_mix` 随选区变化，`filters` 写区名；`district_yoy` 不变，仍是 8 个区。
- 如果你们用阶段一存档点验收，它导出的图表 id 和系列名与上表不同（例如对比图的 id 是 `compare`；房型结构是 `roomtype`，一条系列“房型占比”，`x` 是房型名，点值是套数），照存档点 README 第 4 节改 `ref.sql` 的段头、系列名和取数。
- 降级办法：如果 AI 没有做出导出函数，技术角色改为直接读页面上渲染出来的节点，对照后端接口比对；此时人眼抽查要逐张核对图例与坐标轴。
- 对象 id 与分析角色写的 `ref.sql` 段头一一对应，写法见《ref_sql写法_单元一》。
