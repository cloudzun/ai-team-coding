# 判据筛查清单（四个实战单元共用）

判据是一条能判通过或不通过的检查，写明“怎么判”。写完的判据先筛一遍，筛掉假的，再放进判据清单。

## 一条合格的判据，有四个形状

| 形状 | 自问 | 不合格的样子 |
|---|---|---|
| 能被判 | 机器能跑出通过或不通过，或者人能照表逐项勾选吗？ | “页面体验流畅”：没有人能勾 |
| 换了仍成立 | 换模型、换框架、换界面样式，这条还成立吗？ | “代码里调用了某个库的某个函数”：换一个库就失效 |
| 期望值有来源 | 期望值来自口径表、运营手册、需求、数据库本身吗？ | “入住率应该约为六成”：来源是感觉 |
| 做错会变红 | 故意做错一处，它会不会变红？ | 对错误的实现也通过 |

四个形状缺一个，就先别放进清单。

## 筛假判据的两问

对每一条判据，问两句：

- 问一：**零工作量能不能过？** 什么都不做，或者只做一个空壳，这条会不会判通过？
- 问二：**照错的实现写，会不会被打红？** 举一个具体的错误实现，例如把两组数据装反、联动后图没有重绘、把参考 SQL 原样粘进代码，这条会不会判不通过？

两问里有一问答“能过”或“不会红”，这条就是假判据或弱判据。改法要写清“判什么、怎么判”，不能只写“要更严格”。

想不出机器能判的写法时，不要硬写。降为人眼判据，写进抽查记录表，并写明人要看什么。

## 练习判据

练习情景：下面是为练习编写的 6 条判据，页面是一个有对比图、趋势图和指标卡的数据看板；对比图有“本期”“上年同期”两组柱和一条“市场基准（简单平均）”。判据混合了真的、假的和弱的。

| 编号 | 判据 | 怎么判 |
|---|---|---|
| A | 每个图表的每个系列都有数据，不为空 | 导出图表数据，检查每个系列的点数大于 0 |
| B | 对比图每个区的本期、上年同期、市场基准三个数，按系列名与自写参考 SQL 逐点一致，比例容差 0.001 | 导出图表数据，与参考 SQL 的结果按系列名对齐比较 |
| C | 应用代码里不出现参考 SQL 的文件名 | 在代码里搜索文件名 |
| D | 趋势图让用户感到变化清晰、一目了然 | 人看 |
| E | 在对比图上选中某个区后，导出的指标卡与趋势图的对象集合与参考 SQL 在该区的结果集合逐元素相同（对比图本来就是各区并列，不在此列）；再点一次，集合回到全公司 | 导出图表数据，按集合比对 |
| F | 页面页脚含“模拟数据”字样 | 读页脚文字，检查是否含这四个字 |
