# 民宿托管经营看板 + 问数面板（阶段二存档点）

这是课程单元二收尾时的一种参考实现，不是标准答案。单元一的六个视角、七个接口、区级联动原样保留，问数是加在同一个页面上的第 7 个面板；同一版里还带了区域地图（可选，不配地图密钥就用离线散点）。同样的需求可以有别的目录结构、别的接口切分、别的取数方式——这里给的是“跑得起来、数字能回源、问答记录能导出”的一版，用来对照自己做的面板，或者在自己卡住时拆开看某一类问题是怎么取数的。

页面结构：经营状态（四个指标卡）、月度趋势、各区入住率对比、结构（渠道订单占比与房型结构）、价格分布、房源分布（选区后由地图接管，没配密钥退回离线散点）、问数面板。联动入口不变：右上角的区域选择器、点对比图里的柱子、点房源分布里的散点（配了地图就是点气泡）。问数面板不和区级筛选联动，它按问句里写的区与期间自己取数。

## 2 启动

前提：Python 3.12，并已经有课程数据包里的库文件（数据包在 `v2/kit/`，库在 `v2/kit/db/homestay.db`，是按只读方式使用的同一份数据）。把库复制成存档点根目录下的 `data/homestay.db`——文件名和目录都要一致，`.gitignore` 已忽略 `data/*.db`。

在存档点根目录执行（Windows）：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env                                    # 可选；不填也能启动，问数会返回 503
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8801
```

macOS / Linux 把中间两行换成 `.venv/bin/python -m pip install -r requirements.txt` 与 `.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8801`。已经装了 `uv` 的话，也可以用 `uv venv --python 3.12` 加 `uv pip install -r requirements.txt` 建环境。

打开 <http://127.0.0.1:8801/>。启动时会先把全部聚合算进内存（约 1 秒），之后每个接口直接返回缓存。

**端口被占用时换一个空闲端口。** 缺省端口是 8801。启动报“端口已被占用”，或者浏览器里打开的不是这个看板，就换一个端口：

```powershell
# 先查：没有任何输出，说明 8802 空闲
Get-NetTCPConnection -LocalPort 8802 -State Listen -ErrorAction SilentlyContinue
# 再把启动命令里的 --port 8801 换成 --port 8802
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8802
```

浏览器地址同步换成 <http://127.0.0.1:8802/>；本页后面凡是写到 8801 的地方（打开地址、确认端口释放的命令）都按新端口改。其余步骤不变。

停止：启动窗口按 `Ctrl+C`，再用 PowerShell 确认端口已释放（换了端口就把 8801 改成新端口）：

```powershell
(Get-NetTCPConnection -LocalPort 8801 -State Listen -ErrorAction SilentlyContinue | Measure-Object).Count   # 应为 0
```

启动命令必须在存档点根目录执行：数据库路径写的是相对路径 `data/homestay.db`。

- 库只以 `sqlite3.connect("file:data/homestay.db?mode=ro", uri=True)` 打开，不写库、不建表、不生成任何库文件；想自证这一点，比对启动前后的库文件指纹（SHA-256，用课程材料 `v2/lab/tools/db_fingerprint.py`）即可。
- 依赖只有 `requirements.txt` 里的 14 个 Python 包，没有前端构建链；ECharts 已本地化，页面只请求 127.0.0.1。
- 问数面板会把每次提问与回答写进 `logs/ask.jsonl`（本机日志，不进版本库，可以在 `.gitignore` 里看到）。不想要这份日志，删掉 `logs/` 即可，接口照常工作。

## 3 环境变量（仓库根 `.env`，不进版本库）

环境变量同名且非空时优先于 `.env`。键名与说明见 `.env.example`，这里只列用途：

| 键 | 用途 | 不填会怎样 |
|---|---|---|
| `LLM_BASE_URL` | 问数用的 OpenAI 兼容接口地址 | 问数接口返回 503（`E_LLM`），看板与地图照常 |
| `LLM_MODEL` | 问数用的模型名 | 同上 |
| `LLM_API_KEY` | 模型接口密钥（可选）。有值时请求头加 `Authorization: Bearer …` | 不发这个头；本地无鉴权接口可留空，行为与以前一样 |
| `AMAP_JS_KEY` | 地图 Web 端 Key（会下发到浏览器） | 页面不加载在线底图，自动退回离线散点，不报错 |
| `AMAP_JS_SECURITY_CODE` | 地图安全密钥（只留在服务端，由 `/_AMapService` 代理追加） | 同上 |
| `AMAP_WEB_SERVICE_KEY` | 地图 Web 服务 Key（应用不直接用） | 同上 |

**交付与提问的纪律：只写变量名，不写值。** 值只放在自己机器上的 `.env` 里，不进对话、不进任务书、不进 README、不进提交。代码里也没有任何默认地址或默认模型名——前两个键都没配时不发请求，直接报“未配置模型接口”；`LLM_API_KEY` 不配就不发鉴权头。

想确认配置通没通：打开页面在问数面板里问一句，回答区出来的是正常答案就通了；出来“模型服务不可用”，看页面折行里的原因码，再核 `.env` 的前两项。想故意看降级：把 `LLM_BASE_URL` 指向一个不可达地址再启动，问数报不可用，看板其余部分不受影响。

## 4 接口

| 接口 | 参数 |
|---|---|
| `GET /api/meta` | — |
| `GET /api/kpi` | `district`（空 = 全公司，或 `D01`–`D08`） |
| `GET /api/trend` | `district` |
| `GET /api/compare` | `start`、`end`（缺省 `2026-07-01`、`2026-09-30`；须满足 `2024-10-01 ≤ start ≤ end ≤ 2026-09-30`） |
| `GET /api/structure` | `district` |
| `GET /api/distribution` | `district` |
| `GET /api/geo` | `district` |
| `GET /api/districts` | `start`、`end`（规则同上；缺省同为 `2026-07-01`、`2026-09-30`）→ 每区一行：房源数、入住率本期/上年同期/同比、平均房价、评分、市场入住率、区中心坐标 |
| `POST /api/ask` | `{question}`（1–200 字）→ `{question, mode, answer, steps[], citations[], meta}` |

`POST /api/ask` 的三种返回：

- `mode="query"`：一问一查，`steps[]` 里每步有 `purpose`、`sql`、`columns`、`rows`、`row_count`、`elapsed_ms`；
- `mode="diagnose"`：多步（先取数、再看评论明细、再综合），多出来的字段是 `diagnosis`（结论、发现、建议，值都能回到某一步的结果行）；
- `mode="refused"`：改数据的要求一律拒绝，`steps` 为空，不执行任何 SQL。

模型不可用时返回 HTTP 503 `{"error": "E_LLM", ...}`，不会给出一段编造的回答。`meta` 里有 `llm_calls`、`model`、`elapsed_ms`、`degraded`、`degrade_reason`、`untraceable`；`degrade_reason` 非空表示这一答用了兜底路径（照样给结果，只是不是模型写的那版）。

耗时预期：`query` 约 10–20 秒；`diagnose` 约 30–60 秒。演示时请把页面的加载提示留着，别让观众以为卡住。

## 5 地图（可选）

- 高德 JS API 2.0 脚本由 `map.js` 动态插入并绑 `onerror` 与 10 秒超时；模板里没有静态 `<script src>`。
- 安全密钥不下发到浏览器：页面只设 `window._AMapSecurityConfig = { serviceHost: location.origin + "/_AMapService" }`，由服务端代理转发时追加。
- 没配三个地图变量、脚本加载失败或 10 秒未就绪 → `window.__mapState.provider = "fallback"`，房源分布视角渲染离线散点并显示“地图服务不可用，已切换为离线散点”，`data-state` 仍是 `ready`，不报错。
- 验收时会用到的钩子：`window.__mapState`（`provider` 与当前选中区）、`window.dashboard`（`selectDistrict`、`charts`、`geoProvider`）。

## 6 导出图表与关键数字

页面加载完成（或切完区）后，在浏览器控制台执行：

```javascript
copy(JSON.stringify(await window.__chartExport()))
```

粘到编辑器里存成 `export.json`，供验收脚本与自写参考 SQL 对账。返回对象与阶段一存档点同一套契约：

| 字段 | 内容 |
|---|---|
| `page` | 固定 `dashboard` |
| `filters` | 当前筛选状态，`{"district": "全公司"}` 或区名 |
| `kpis` | 四个指标卡：`id` 为 `occupancy_latest`、`adr_latest`、`revpar_latest`、`rating_latest`；`value` 是渲染时的数值，`label` 是页面显示文字 |
| `charts` | 六个图表对象：`id`（`trend`、`compare`、`channel`、`roomtype`、`distribution`、`geo`）、`title` 区块标题、`series` 系列数组，点结构为 `{x, value, label}` |

### 图表 id 与系列名

用存档点验收时，`ref.sql` 的段头和系列名要照下表写（系列名要逐字一致，包括括号）：

| 图表 id | 视角 | 系列名 | 点的 `x` | 点的 `value` | 选区后 |
|---|---|---|---|---|---|
| `trend` | 月度趋势 | `入住率`、`平均房价` | 年月 | 入住率为 0 到 1 的小数；平均房价为元 | 按所选区重取 |
| `compare` | 各区入住率对比 | `本期`、`上年同期`、`市场基准（简单平均）` | 区名，固定 8 个区 | 入住率，0 到 1 的小数 | **不变**，仍是 8 个区 |
| `channel` | 渠道订单占比 | 每个渠道一个系列，系列名就是渠道名 | 季度（如 `2025Q3` 的写法） | 占比，0 到 1 的小数 | 按所选区重取 |
| `roomtype` | 房型结构 | 一个系列 `房型占比` | 房型名 | **在线房源套数**（不是占比；饼图扇区上显示的百分比在 `label` 里） | 按所选区重取 |
| `distribution` | 价格分布 | `最小值`、`下四分位`、`中位数`、`上四分位`、`最大值` 五条系列 | 房型名 | 每晚价，元 | 按所选区重取 |
| `geo` | 房源分布 | 每个区一个系列，系列名就是区名 | 房源编号 | 纬度 | 按所选区重取 |

取值来源只有两处：图表实例的当前配置（ECharts `getOption()`）与页面节点（指标卡节点的数值属性与显示文字、区块标题、筛选控件的当前值），不重新请求接口、不转发接口返回的原始数据。切区后各视角要重新取数，导出函数会等到没有“加载中”的区块再返回，所以用 `await` 拿结果。

几个约定：

- 系列与点位直接对应画布上已经画出来的数据：折线、柱状、散点按系列导出；箱线图的每个箱体拆成五条系列；饼图一条系列，点名作图。
- `label` 只在画布上真的显示了数值文本时才有值（饼图扇区上的百分比），其余图表的点位没有数值标签，`label` 为 `null`。
- 数值统一保留 6 位小数，用于去掉二进制浮点的尾数噪声。
- 房源分布图是经纬度散点，导出为“系列 = 区名，点 `x` = 房源编号，`value` = 纬度（4 位小数）”；导出契约每个点只有一个数值，经度没有单列，页面上悬停提示里经纬度都在。

## 7 已知的口径歧义与参考实现的取舍

界面上的数字都能回源到 `docs/指标口径表.md`，下面几处是这一版实现自己的取舍，验收时按这里写明的口径理解，别按别的口径反推：

1. **指标卡的 `value` 比页面文字更精确**：卡片渲染时把未截断的数值写在节点的 `data-value` 上，导出读这一份，所以 `value` 可能是 `0.1234` 这样的四位小数，而同一张卡片 `label` 显示 `12.3%`。四条指标卡的精度分别是：入住率 4 位小数、平均房价 2 位小数、每间可售房收入 2 位小数、平均评分 2 位小数（舍入方式为 half-up）。
2. **对比图的市场基准是简单平均**：对该区在该期间内所有市场基准行（分行型、分月）取算术平均，不按可售晚数加权。它和“自己”的加权口径不同，所以市场基准与本期两条柱子相减，只是个粗略参照。
3. **对比图不随区级筛选变化**：它固定画全公司 8 个区，选中区只把柱子与区名高亮，不改变数据；缺省区间是 2026 年三季度（数据截止日所在季）对上年同期，`/api/districts` 的缺省区间与它一致。
4. **价格分布的须线是最小值与最大值**：箱线图按最小、下四分位、中位数、上四分位、最大五个数画，没有按 1.5 倍四分位距剔除异常值。
5. **趋势图画了入住率与平均房价两条线**：每间可售房收入与平均评分在数据里、也在这张图的悬停提示里，但没有单独画线，导出也只含画出来的两条系列。
6. **结构视角两处口径**：渠道订单占比含取消单（口径表 M-10 允许，但要求注明），按订单入住月归属到季度；房型结构是截至 2026-09-30 仍在线的房源数。
7. **评分样本不足**：当月有效评分少于 5 条时，页面显示“样本不足”，导出里 `value` 为 `null`、`label` 保留页面文字；本次数据下全公司当月不是这种情况，换成某个区、某个时间窗可能出现。
8. **评分的“当月”按评论日期归属**：平均评分按评论日期（`reviews.review_date`）所在月份统计，不按评论所属订单的入住日；两种归法的结果一般不同，自己写参考 SQL 时要照这一条。
9. **比例的四舍五入**：库内中间结果按 half-up 保留 4 位小数（金额与评分 2 位），页面按 1 位小数百分比展示，展示值可能与精确值最多相差 0.05 个百分点。
10. **问数里的“低分口径”与“样本门槛”取运营手册的字面值**：评论类问题没有在问句里写评分线时，按手册 Q-01 的观察线；没有写样本条数时，按手册 Q-05 的样本门槛。这两个数是手册值，不是标准答案里的数；换一组值命中的评论集合就会变，是正常的。
11. **问数的“当期”按评论日期**：diagnose 里评论明细的时间窗按 `reviews.review_date` 过滤；问句没写期间时按数据全覆盖期，不凭空加窗口。
12. **地图模式下 `geo` 导出为空**：配了地图密钥时，房源分布视角由高德地图接管，ECharts 散点不初始化，`chart_export.js` 的 `geo` 段就没有系列。要用 `geo` 对账就别配地图密钥（走离线散点）。这是这一版的已知瑕疵，不影响其余五个图表。

## 8 从单元一到单元二

单元二是单元一的**严格超集**：单元一的六个视角、七个接口、区级联动全在，问数是加在同一个页面上的第 7 个面板。所以“切到单元二”有两条路，选一条走到底：

- **沿用自己的单元一成果（课内主线）**：在单元二的起点步骤里，把自己的看板当基线，在它上面加问数面板。你自己的验收脚本、`ref.sql`、导出契约都继续用。
- **切换到这个存档点**：按第 2 节把库放好、装依赖、起服务。换过来之后：页面是参考实现（不是你的实现），你自己的验收脚本、`ref.sql` 还能继续用，但要按第 6 节的图表 id 与系列名核对——如果你自己的图表 id 和这里不一样，`ref.sql` 的段头要跟着改。

切换后要重新验的三件事：

1. 第 6 节的 `window.__chartExport()` 能拿到完整 JSON（六个图表 + 四个指标卡）。**没配地图密钥也能拿到**；配了密钥时 `geo` 段为空，见第 7 节第 12 条。
2. 不做任何写入：库只读打开，跑完一轮接口后库文件指纹（SHA-256）应与启动前一致。
3. 问数面板要么给出能回到 `steps[]` 结果行的回答，要么明确报不可用（503 `E_LLM`）——两者都算对，编造数值不算。

## 9 校正过的几处

- 模型接口地址与模型名只从配置读，代码里不留默认值：没配就报“未配置模型接口”，问数返回 503，不会连到别人的服务上。
- 提示词里举例不再点具体区名，改成“按问句里的区名原样写”。
- 对比类接口的缺省区间统一为数据截止日所在季（`2026-07-01` ~ `2026-09-30`），与阶段一、阶段三存档点一致。
- 评论类问题的兜底口径取运营手册字面值（见第 7 节第 10 条），不再用参考实现里另设的数。
- 本 README 只写启动、变量名、接口、导出契约与口径取舍；数据生成方式、验收判据、试跑记录见课程材料。
