# 运营手册

> 适用于托管公司全部房源（模拟数据）。巡检 Agent 的每条建议都必须引用本手册的规则编号；指标按《指标口径表》计算。
> 规则编号前缀：P 定价，Q 质量，F 整改流程，N 不调价情形。

## 1 定价规则

| 编号 | 规则 |
|---|---|
| P-01 | 单次调价幅度上限为 **15%**（涨或降都算，以当前平日价为基数）。超过上限的申请一律驳回。 |
| P-02 | 周末价（周五、周六晚）应高于平日价，溢价区间为 15%–35%。 |
| P-03 | 旺季（7 月、8 月、国庆假期）由系统规则在当前价格上自动上浮，人工不再另行加价；春节期间系统规则小幅下浮。 |
| P-04 | 淡季入住率下滑属季节性波动的，先与上一年同月比较（同比），同比无明显下滑时不调价。 |
| P-05 | 房源平均房价与同区同房型市场均价相差超过 **±20%**，触发人工复核。按差距需要调整的幅度超过 P-01 上限时，只能先申请上限以内的幅度，并在申请中写明完整差距和“需人工评估”。 |
| P-06 | 调价必须通过“调价申请”提交，写明原价、拟调价、幅度、理由和证据引用；申请经人工批准后才生效，任何人不得直接修改价格记录。 |
| P-07 | 判断定价是否有问题，先排除大盘因素：自身入住率下滑而同期市场入住率基本持平，才可归因于自身定价或产品。 |

## 2 质量红线

| 编号 | 规则 |
|---|---|
| Q-01 | 房源当季平均评分低于 **4.5**（样本不少于 5 条）进入观察名单。 |
| Q-02 | 任一子评分连续两个月下降，触发排查：先看同期评论在说什么，再定问题类型。 |
| Q-03 | 同一问题主题在某房源（或同一小区的一组房源）当期评论中占比超过 20%，视为集中问题，进入整改流程。 |
| Q-04 | 评论主题归纳只说明“评论里集中提到了什么”，每条归纳必须附评论原文 ID。 |
| Q-05 | 样本不足（少于 5 条）时只记录，不下结论。 |

## 3 整改流程

| 编号 | 步骤 |
|---|---|
| F-01 | 问题分类：从“噪音、清洁、入住指引、设施、沟通、位置描述、其他”中选一类，附证据（指标数字与评论 ID）。 |
| F-02 | 开工单：提交整改工单（待审批），同一房源同一问题已有未关闭工单时不重复开单。 |
| F-03 | 通知房东：工单批准后生成通知邮件草稿，发往房东登记邮箱；邮件只生成到本地，不直接发送。 |
| F-04 | 复查：整改完成后满一个月复查对应子评分与主题占比；已回升的关闭工单，未回升的升级处理。 |
| F-05 | 问题不在价格（如噪音、入住指引）时，整改优先，不以降价代替整改。 |

## 4 什么情况不调价

| 编号 | 规则 |
|---|---|
| N-01 | 房东关房期间、以及成交晚数低主要由房东关房造成时，不调价。关房不算空置（见口径表 T-01）。 |
| N-02 | 样本不足时不调价：评论少于 5 条，或当期可售晚数少于 15 晚。 |
| N-03 | 整改期内（存在未关闭的整改工单）不调价。 |
| N-04 | 新上线不满 30 天的房源不调价。 |

## 5 建议的输出格式

每条巡检建议至少包含：房源 ID、问题、证据（可在库里查到的数字、评论 ID）、引用的规则编号、建议动作（调价申请 / 整改工单 / 不处理）、是否需要人工评估。
